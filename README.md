# 🃏 CertOfChaos

> *Why so serious about certificates?*

A GUI utility for generating self-signed code-signing certificates and applying them to PE executables. Built for **security researchers, red teamers, and penetration testers** who need to understand and test how code-signing validation behaves in controlled lab environments.

## What It Does

CertOfChaos lets you:

- Generate **random or custom self-signed code-signing certificates** (RSA 2048/3072/4096, SHA-256/384/512)
- **Sign PE executables** (`.exe`) using `osslsigncode` (Linux/macOS) or `signtool` (Windows)
- Perform **single or batch signing** with optional per-file random certificates
- **Export** certificate files (`.pfx`, `.pem`, `.cer`)
- **Verify** signatures on signed files
- Save and reload **certificate presets**
- Optionally attach a **RFC 3161 timestamp** from a selection of public servers

## Legitimate Use Cases

- **Red team lab work**: Testing how endpoint security products respond to signed vs. unsigned payloads in isolated, authorized environments
- **Security research**: Understanding Windows Authenticode, PE signing, and certificate validation workflows
- **CTF / training environments**: Practising certificate generation and binary manipulation techniques safely
- **Developer tooling**: Quickly generating test certificates for internal development pipelines where a commercial cert isn't needed

## Usage

```bash
python signer.py
```

The GUI will open. Navigate the tabs:

| Tab | Description |
|---|---|
| ✍ Single Sign | Sign one EXE with a generated certificate |
| 📦 Batch Sign | Sign multiple EXEs, optionally with a unique cert per file |
| 🃏 Certificate | Customise or randomise certificate fields; export cert files |
| ⚙ Settings | Select timestamp server, hash algorithm, RSA key size |

---

## Important Notes on Self-Signed Certificates

Certificates generated by this tool **will not be trusted by Windows SmartScreen, Microsoft Defender, or any OS trust store** — they have no chain to a public CA. They are useful for:

- Testing how security software responds to *any* signed binary vs. an unsigned one
- Signing binaries for internal/lab use where only your own trust store matters
- Research into how signing metadata appears to analysis tools

They are **not** a substitute for a commercially issued code-signing certificate for legitimate software distribution.
